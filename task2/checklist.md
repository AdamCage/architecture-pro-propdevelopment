# Проверочный лист безопасности для бизнес-систем PropDevelopment (Task2)

## 1) Охват систем (по диаграмме и описанию)
- **Контур клиентов (продажи):** Витрина продаж (React), client-crm-app (+ MSSQL), client-mart-app (+ Postgres), client-mart-estate-app (+ Postgres), client-tour-app (+ Postgres), интеграция с госорганами (SOAP/СМЭВ).
- **Контур собственников (ЖКУ):** мобильная витрина (iOS/Android), tenant-core-app (+ Postgres), CRM собственников (+ Postgres), интеграции с поставщиками ЖКХ и платёжной системой.
- **Финансы:** accountant-service-1, каталоги (AD), БД auth-db-1.
- **Данные:** DWH (Greenplum + S3) + CDC из БД доменов.

## 2) Почему выбран именно этот состав разделов
Приоритеты PropDevelopment в исходном кейсе:
- **Нарушен контроль данных** (ошибки отображения чужих данных, нет системного контроля потоков, в контуре данных отсутствуют ограничения доступа).
- **Риски во внешних интеграциях** (партнёрские API содержат ПДн и допускают несанкционированные действия/доступ между УК).
- **Подготовка к аудиту безопасности и соответствие законодательству РФ**.

Поэтому в чек-лист включены базовые разделы из шаблона (IAM, защита данных, инфраструктура, инциденты) и добавлены 2 специализированных блока:
- **V.3 API и внешние интеграции** — чтобы закрыть ключевую проблему партнёрских API и будущих сервисов «умного дома».
- **V.4 Контур данных (DWH/BI/CDC) и Data Governance** — чтобы адресовать отсутствие ограничений доступа и управляемости данных.

Примечание по заполнению: поле **«Да/нет»** заполнено только там, где информации из кейса достаточно. Остальные пункты отмечены комментариями «требует уточнения в ходе аудита».
